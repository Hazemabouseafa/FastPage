# FastPage — Starter (مرحلة التشغيل اليدوي)

**مشروع تجريبي قابل للتشغيل، وليس نشرًا فعليًا على الدومين.**

## فكرة النسخة
- موقع رئيسي لتسويق باقة الصفحة الواحدة بسعر **1,000 جنيه**.
- 3 قوالب مستقلة: شركات/خدمات، مطاعم/كافيهات، وبراند شخصي.
- نظام توزيع صفحات بناءً على اسم Subdomain، من تطبيق Node واحد.
- العميل الجديد = **ملف JSON واحد** (لا يحتاج مشروعًا أو استضافة منفصلين).
- تصميم RTL متجاوب مع الموبايل؛ لا توجد قاعدة بيانات أو لوحة تحكم أو تسجيل دخول في المرحلة الأولى.
- مناسب لاحقًا لإضافة PostgreSQL ولوحة تحكم ونظام اشتراكات، مع إعادة استخدام القوالب.

## تشغيل محليًا

1. ثبّت **Node.js 20 أو أعلى**.
2. افتح مجلد `fastpage-starter` من الـTerminal.
3. شغّل `npm start`، ولا يحتاج `npm install` لأن المشروع بدون مكتبات خارجية.
4. افتح: `http://localhost:3000`.
5. القوالب: `http://localhost:3000/preview/demo` و`/preview/coffee` و`/preview/portfolio`.
6. مثال عميل: `http://localhost:3000/preview/ahmed`.
7. لاختبار التوجيه بالنطاق الفرعي: `curl -H "Host: ahmed.fastpage.my" http://127.0.0.1:3000/`.

للتطوير التلقائي استخدم `npm run dev`. الاختبارات: `npm test`.

## إضافة عميل جديد (يدويًا)

1. اختار اسمًا لاتينيًا قصيرًا للعميل مثل `nour-beauty`.
2. انسخ ملفًا من `data/sites/` مثل `demo.json` ثم احفظه باسم `nour-beauty.json`.
3. عدّل بيانات `name` و`headline` و`description` و`services` و`about` و`whatsapp` و`theme`.
4. استخدم `"template": "business"` أو `restaurant` أو `portfolio`.
5. **صور العميل**: ضَع صور JPG أو PNG أو WebP في `public/media/`، واكتب في ملف JSON:
   - `"heroImage": "/media/business.webp"` لقالب الأعمال أو المطعم.
   - `"avatarImage": "/media/profile.jpg"` لقالب البراند الشخصي.
   - داخل كل عنصر في `products` استخدم `"image": "/media/product-1.webp"` لصور المنتجات.
   استخدم أسماء صور لاتينية بأحرف وأرقام وشرطة.
6. استخدم رقم واتساب دولي **بالأرقام فقط**، مثل `20` ثم رقمك المصري بدون صفر البداية. لا تستخدم رقمًا وهميًا أو رقم عميل غير مصرح به.
7. لو العميل ليس نموذجًا: `"isDemo": false`، ولو الموقع غير جاهز: `"published": false`.
8. عاين على `/preview/nour-beauty` ثم راجع كل شيء وانشر البيانات. بعد تفعيل الـDNS والرابط الإنتاجي، الصفحة تظهر على `https://nour-beauty.fastpage.my`.

**ملحوظة:** هذه النسخة تقرأ JSON من القرص في كل طلب، ومناسبة للبداية. تجنب تخزين كلمات مرور أو معلومات حساسة في ملفات JSON.

## التواصل

- عرّف متغير البيئة `CONTACT_WHATSAPP` على السيرفر عشان زر «اطلب صفحتك» في موقع FastPage الرئيسي يفتح واتساب الخاص بك. مثال: `CONTACT_WHATSAPP=2010XXXXXXXX` (غيّر X إلى أرقام فعلية).
- جهّز بريد `hello@fastpage.my` لو هتستخدم رابط البريد البديل في القالب، أو غيّر الرابط/احذف البديل قبل النشر.
- مواقع العملاء لديها حقل WhatsApp خاص بها. إذا كان فارغًا، سيذهب زر التواصل إلى قسم التواصل داخل الموقع بدل فتح واتساب.

## النشر على VPS باستخدام Coolify (مُجهّز بالكامل)

المشروع مُجهّز بـ `Dockerfile` وإعدادات الشبكـة (`0.0.0.0`) وفحص الحالة (`/health`) ليعمل مباشرة على **Coolify**:

1. من لوحة تحكم **Coolify**، أضف مشروعًا جديدًا واختر **Public Repository** أو **GitHub App** واربط مستودع `FastPage`.
2. في إعدادات **Build Pack** اختر **Dockerfile** (أو **Nixpacks**، كلاهما مدعوم).
3. في خانة **Ports Exposes** تأكد أنها مضبوطة على `3000`.
4. في خانة **Domains** ضع الدومين الأساسي والنطاق الفرعي (Wildcard) معًا بهذا الشكل:
   `https://fastpage.my,https://*.fastpage.my`
5. في قسم **Environment Variables** يمكنك تعديل المتغيرات عند الحاجة (القيم الافتراضية مضبوطة مسبقًا):
   - `PORT=3000`
   - `BASE_DOMAIN=fastpage.my`
   - `CONTACT_WHATSAPP=201550612361`
6. اضغط **Deploy**؛ سيقوم Coolify ببناء الحاوية وتشغيلها وتفعيل الفحص التلقائي عبر `/health`.

## النشر اليدوي على VPS (خطة بديلة بدون Coolify)

هذه الخطوات تحتاج **ملكية الدومين + حساب Cloudflare + VPS**، ولم تُنفذ تلقائيًا.

1. أضف `fastpage.my` إلى Cloudflare وقم بتحديث الـNameservers من المسجل إذا كنت تريد Cloudflare Full Setup.
2. أنشئ سجل DNS `A` للاسم `@` يشير إلى IP السيرفر، وسجل `A` للاسم `*` يشير لنفس IP، وكلاهما **Proxied**.
3. ثبّت Node.js 20+ وNginx على VPS، وارفع المشروع في `/opt/fastpage`.
4. شغّل التطبيق كخدمة خلف Nginx (ملفات إرشادية في مجلد `deploy/`).
5. أنشئ Cloudflare Origin CA certificate يغطي `fastpage.my` و`*.fastpage.my`، وثبّته بأمان داخل Nginx (ملف المفتاح السري لا يدخل Git).
6. اضبط SSL/TLS في Cloudflare على **Full (strict)** بعد تفعيل شهادة صالحة على السيرفر، واختبر `https://fastpage.my` و`https://demo.fastpage.my`.
7. طبّق جدار حماية، تحديثات أمنية ونسخًا احتياطية للبيانات والملفات.
8. **قبل الإطلاق:** اضبط رقم واتساب حقيقي، محتوى قانوني أساسي، تفاصيل الاستضافة وتجديد السنة الثانية، وسياسة استخدام واضحة.

المراجع: https://developers.cloudflare.com/dns/manage-dns-records/reference/wildcard-dns-records/ و https://developers.cloudflare.com/ssl/origin-configuration/ssl-modes/full-strict/

## ضوابط مهمة

- استخدم اسم Subdomain فريد، بصيغة `a-z`, `0-9`, `-` فقط، وبحد أقصى 63 حرفًا، ولا تحجز أسماء مثل `admin`, `www`, `api`.
- لا تضع عنوان العميل أو سعره أو صوره دون موافقته؛ البيانات الحالية **نماذج خيالية وليست مراجعات/مشاريع حقيقية**.
- الأسعار داخل قالب الكافيه أمثلة توضيحية فقط، غيّرها قبل التسليم.
- قم بعمل نسخ احتياطية من ملفات JSON وملفات المشروع بصورة دورية.
- في خدمة الـ1,000 جنيه، حدّد بوضوح عدد الأقسام وعدد جولات التعديل ومدة التسليم والتجديد السنوي.
- هذه النسخة لا توفر لوحة تحكم ولا مدفوعات تلقائية ولا إحصائيات ولا إنشاء نطاقات متقدم؛ هذه وظائف لاحقة.

## التحويل إلى منصة مستقبلًا

- نقل ملفات JSON إلى قاعدة PostgreSQL (جدول `sites`: slug, template, data JSONB, status, billing renewal_date).
- بناء Admin Panel محمية بتسجيل دخول وصلاحيات لإضافة العملاء والتعديل.
- محرر محتوى للعملاء حسب الباقة، ونظام نشر/مسودات.
- إدارة الاشتراكات والتذكير بالتجديد والدفع.
- لاحقًا دعم ربط الدومين الخاص بالعميل وربط النطاق تلقائيًا وإحصائيات الزيارات وفق متطلبات الخصوصية.

> تنبيه: المثال في `deploy/nginx.conf` نموذج إعداد للإرشاد ويحتاج مراجعة أمنية وتجربة على بيئة السيرفر قبل استخدامه في الإنتاج.
